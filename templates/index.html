About this project

Why this exists

Every year, more than 20 lakh students appear for the NEET-UG examination to compete for a limited number of medical seats across India. Choosing the right college during counseling is genuinely hard: allotment depends on NEET score, category, quota, state eligibility, rank, and previous years' cutoff trends, and most students end up piecing this together from manual research, counseling agents, or scattered forum posts.

The objective of this project is to build a machine-learning-based NEET College Prediction System that estimates the most likely medical college for a student, based on their NEET rank and reservation category, trained on real NEET UG 2025 Round-3 college allotment data — so students get a data-driven starting point during counseling instead of guesswork.

What it predicts from

The system takes three student-facing inputs and returns a ranked, probability-scored list of likely colleges:

AIR (All India Rank) Gender Category / Quota

These are the only three fields in the source dataset that are legitimately predictive and available before counseling — identifying fields (name, roll number, form number) were dropped as PII with zero predictive value, and two columns (College Code, Remark) were deliberately excluded from training because they are near-duplicates of the answer itself (see the honesty note below).

How the model was built

Dataset

NEET_2025_MBBS_BDS_Round3_SelectionList.xlsx — 29,165 candidate rows with columns for AIR, Gender, Category/Quota, College Code, College Name & Status, and Remark.

Cleaning

  • Standardised Gender and Category/Quota text (trim + uppercase).
  • Repaired truncated college-name strings (unclosed brackets from the raw export).
  • Dropped PII columns (Name, NEET Roll No, CET Form No, Sr.No) — unique identifiers with no predictive signal.

Building the target

The raw College Name & Status field mixes the college name with a round-status suffix, e.g. GSMC MUMBAI(Ret.) vs GSMC MUMBAI(No Pref). The status suffix was stripped so the model predicts the college itself (98 distinct colleges), and two additional outcome classes were added for candidates who weren't allotted a seat in this round — NOT_ALLOTTED and DISQUALIFIED — giving 100 total outcome classes and using 100% of the rows, with nothing dropped for a missing target.

Feature engineering

Category/Quota had 404 raw distinct strings after cleaning; categories occurring fewer than 30 times were grouped into an OTHER bucket (404 → ~76 groups), then frequency-encoded. Gender was binary-encoded. No scaling was applied, since every model tested is tree-based and scale-invariant.

Models compared

Decision Tree, Random Forest, XGBoost, LightGBM and CatBoost were each trained independently (no pipeline wrapper) on an 80/20 stratified split, and evaluated on Accuracy, Top-3 Accuracy, Macro F1 and Weighted F1 — Macro F1 in particular, since with 100 imbalanced classes accuracy alone is misleading. See the live comparison table above.

Honest accuracy note

This is the part most prediction tools don't tell you, so we're putting it front and center.

This model will not hit 90–92% accuracy, and it shouldn't. Real counseling allotment is driven by a candidate's rank, category, and the ordered list of college preferences they filled, weighed against how many seats were still open that round. This dataset contains rank, category and gender — but not preference order or the live seat matrix. Two candidates with an identical rank and category can land in different colleges purely because they filled different preference lists. No model can recover information that was never in the data.

Some context that makes the ~66% Accuracy / ~78% Top-3 Accuracy numbers meaningful rather than disappointing:

  • A trivial baseline that always predicts NOT_ALLOTTED already scores about 61.8%, because that genuinely is the majority outcome in Round 3. The best model here is only a few points above that floor — a real but modest signal.
  • Feeding College Code back in as a feature pushes accuracy far higher artificially — but that's not a real prediction. College Code and College Name are two labels for the same seat, so the model would just be memorising the answer key. This was tested and shown in the notebook purely to demonstrate the leakage, not as a number to ship.
  • If you need materially higher accuracy, the honest fix is more relevant data — previous-round cutoff ranks per college/category, the seat matrix per round, and ideally the candidate's own choice list — not a different algorithm.
Treat every prediction on this site as a probability-ranked shortlist to research further, not a guarantee of your Round-3 outcome.

Tech stack

pandas / numpy scikit-learn XGBoost LightGBM CatBoost Flask joblib AWS EC2

Model selection, training and the pickle export happen in NEET_College_Prediction.ipynb. app.py loads the exported model bundle once at startup and serves this page plus a small JSON prediction API; no retraining happens on request, so predictions return in well under a second.
